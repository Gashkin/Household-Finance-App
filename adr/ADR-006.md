# ADR-006: Maintain Planner API Contract During Storage Migration
- Status: Accepted
- Date: 2026-07-13
- Context: Frontend planner workflows already depend on `/planner` commitment payload shape and CRUD endpoints while backend storage is being restructured.
- Decision: Keep planner API behavior and commitment-oriented endpoint contract stable during migration, while internally routing persistence to `monthly_commitments` and `transactions`.
- Constraints: API compatibility takes precedence over immediate endpoint redesign. Endpoint redesign, if required, must be introduced as additive versioned contracts.
- Rules out: Breaking API changes to planner commitment payloads during the table-split rollout.
- Supersedes: None
