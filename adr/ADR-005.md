# ADR-005: Split Commitments Persistence Into Monthly Definitions And Transaction Instances
- Status: Accepted
- Date: 2026-07-13
- Context: The single `commitments` table mixes recurring payment definitions with dated one-off entries, which blocks clean grid behavior and weakens snapshot traceability.
- Decision: Persist recurring planner commitments in `monthly_commitments` with `day_of_month`, and persist dated financial instances in `transactions` with `txn_type` values (`ACTUAL`, `MONTHLY_INSTANCE_FUTURE`, `ONE_OFF_FUTURE`).
- Constraints: Current month snapshot calculations must aggregate from `transactions`. Monthly grid writes only to `monthly_commitments`. One-off grid writes only to `transactions` where `txn_type = ONE_OFF_FUTURE`.
- Rules out: Continuing long-term with a single mixed-purpose commitments table.
- Supersedes: None
