## Domain in One Paragraph
The system is a household finance tool that replaces a spreadsheet by helping the primary planner manage commitments and actual transactions while giving the secondary consumer a simple, trustworthy view of cashflow and allowable spend.

## Core Entities
- Accounts and balances
- Income sources
- Expenses and bills
- Transactions
- Categories and tags
- Monthly time periods
- Planned vs actual financial position

## Primary Journeys
1. Review household cashflow and allowable spend
2. Add or update recurring commitments
3. Add or update one-off commitments
4. Import or enter actual transactions
5. Reconcile planned vs actual and investigate deviations
6. Review the household financial picture at a high level

## Non-Negotiables
- It must not put the complexity on the user
- It should be easy to use
- It should not forecast generously; it needs to provide a real picture
- It should not miss transactions, because that would break trust
- The numbers must add up
- We must be able to trust that everything is in sync
- If the system says we have enough cashflow for the expenses we do, that must be true

## Explicit Exclusions
- The system should seed its data from the existing spreadsheet
- It should not include the random other spreadsheets that are not part of monthly budgeting
- Specific event financial planning such as Christmas and holidays
- Tax calculations

## Known Uncertainties
- The biggest uncertainty is how transaction automation should work
- If scope had to be cut, automating transactions would be the first thing to cut
- The exact design of that automation is still uncertain
