# Enable Banking sandbox connection (GBD-10)

This build connects **Mock ASPSP synthetic EUR accounts only**, using Enable Banking's SANDBOX application, AIS consent and server-signed requests. Production applications are rejected. No payments API is implemented. AIB is not validated by this story; [GBD-14](https://www.notion.so/418d3419fef081808864ca465d4eff7a) tracks production eligibility, security readiness and owner-authorised AIB validation after GBD-10.

## Local setup

1. In the provider control panel, verify your application is active, SANDBOX, AIS enabled and MFA protected. Register this exact callback: `http://127.0.0.1:5173/bank/callback` (or your explicitly configured loopback port). Never use real-bank credentials in the mock flow.
2. Keep the RSA signing key on the backend machine, outside this repository, with owner-only permissions. PKCS#8 `BEGIN PRIVATE KEY` PEM, RSA at least 2048 bits. Do not paste keys into chat, terminal command arguments, GitHub, Notion or browser forms. On Windows run `./Configure-BankingSandbox.ps1` to copy a locally downloaded key to an ACL-protected private folder and set this PowerShell session's environment. On Linux use a private directory and `chmod 600` on the PEM; supply its path through `BANK_SANDBOX_KEY_PATH`.
3. Set `BANK_SANDBOX_ENABLED=true`, `BANK_SANDBOX_APP_ID` to the application UUID and `BANK_SANDBOX_KEY_PATH` to that private file. `BANK_SANDBOX_CALLBACK` defaults to the callback above. Start backend/frontend using the README in this same shell. Signing material is read server-side for explicit requests; no key is displayed by the application.
4. Unlock the local workspace. In Money position create a cash or debt ledger with a dated start-of-day opening statement. Confirm synthetic-only consent, check the application and load Mock ASPSP, then connect. Complete consent on the provider page. The callback is state-bound to your original workspace session and expires after ten minutes. Keep that browser session open throughout consent.
5. Choose the authorised synthetic account and matching local ledger; select at most 90 days and explicitly fetch. All pages must succeed before a preview appears. Review classifications, pending/booked status, duplicates/overlaps and approve. Informational booked balance evidence never overwrites the ledger or reconciles it automatically. Reconcile explicitly before publishing a cash position.
6. Disconnect and revoke when finished. Failed revocation blocks refresh and permits retry; local forgetting is a separate action and does not revoke provider consent. Restarting the backend forgets connection state; revoke abandoned consent in the provider control panel as needed. Reconnect using the same ledger: hashed account identity and stable entry references detect duplicate activity.

## Protection and limits

- Closed AIS endpoint allowlist, fixed API host, HTTPS transport, checked SANDBOX metadata, approved redirect hosts, five-minute RS256 JWTs. No production endpoint override or payment consent.
- Workspace authentication and mutation CSRF/origin controls protect endpoints. Callback query is erased before app network requests; no tokens/codes/session references in browser storage, logs, backup records or UI. Provider session/account references live only in backend memory, consent lasts at most one hour, and no background refresh exists.
- Limits: 256 KiB per provider response (including chunked bodies), eight-second request wait, 50 pages/500 rows, bounded fetch deadline, 20 refresh attempts per session, five connection attempts per minute. Unsupported currency/status, missing stable identity, repeated pages/references, expired/revoked consent and partial failure fail closed.
- Stored data: approved ledger facts/audit/provenance and hashed account mapping. Disconnect retains reviewed financial evidence. Encrypted workspace backups retain it too; restore can reintroduce deleted records. Full workspace removal follows private-workspace.md; remove obsolete backups and signing keys separately. Local deletion does not revoke consent. There is no production claim: live H2 files require protected OS storage/device encryption and GBD-14 must address real-data readiness and granular deletion.
- Private key files reject group/world access or unsupported ACL storage and repository placement. Windows setup depends on Windows ACL support; key rotation means replacing/restricting the local file and revoking the old provider key/application as appropriate. Do not publish the local app.

## Verification boundary

Automated tests use an ephemeral local synthetic provider, generated RSA keys and a mock consent page. That fixture exists in test sources only and is not packaged in the runnable jar. Tests exercise the real HTTP/JWT protocol, pagination, review-before-write, reconnection, callback binding/replay/expiry, production/payment rejection, oversized/partial failures, key permissions, revocation and desktop/mobile UI. They do not demonstrate a successful request to the registered Enable Banking service. That final sandbox smoke test requires the owner's locally provisioned key; no key is available to the coding agent. Do not label it externally verified until the operator performs that flow.
